# v1.0.4 - SonarQube Cloud Analysis and Dependency Refresh

## Summary

This release adds SonarQube Cloud static analysis to CI, tightens workflow
permissions, refreshes outdated CI/pre-commit/test-image pins, and cleans up the
Python coverage tooling and test image so they pass static analysis. The router
scripts behave exactly as they did in v1.0.3.

## What Changed

### 1. SonarQube Cloud

- Added the root [`sonar-project.properties`](../../sonar-project.properties) file
  (organization `ventura8`, project key
  `ventura8_Synology-SRM-Bing-Wallpaper-Auto-update`).
- Added a `sonarqube` job to [`ci.yml`](../../.github/workflows/ci.yml). It uses the
  pinned `SonarSource/sonarqube-scan-action` v8.2.2 and runs after `quality`. It
  needs the `SONAR_TOKEN` repository secret. When the secret isn't available (for
  example on fork PRs), the job skips with a notice.
- Added a SonarQube Cloud quality gate badge to the README.
- Coverage is still checked only by the kcov ≥90% gate. SonarQube Cloud can't read
  kcov's shell coverage, so its coverage import is turned off.
- `NOSONAR` is now a forbidden suppression in
  [`tools/check_forbidden_suppressions.py`](../../tools/check_forbidden_suppressions.py).

### 2. Static-Analysis Cleanup

- `ci.yml` now sets `permissions: contents: read` for the whole workflow. Only the
  coverage report job gets extra access (`pull-requests: write`); the unused
  `contents: write` and `checks: write` grants were removed.
- `release.yml` moved `contents: write` from the workflow level to the `release` job.
- Workflow shell expansions (`$GITHUB_OUTPUT`, `$GITHUB_STEP_SUMMARY`, `$PWD`)
  are now quoted.
- `tools/coverage_metrics.py` now passes a `ComplexityPolicy` dataclass instead of
  functions with 8 parameters. The column-width and bullet-list code moved into
  small helpers to reduce complexity. Output is unchanged.
- In `check_line_length.py`, `check_forbidden_suppressions.py` and
  `coverage_metrics.py`, `if`/`return` blocks were simplified, as suggested by ruff.
- `tests/Dockerfile` builds the mock SRM filesystem in one layer, uses `printf`
  instead of `echo`, and builds kcov with `cmake -S/-B` instead of `cd`.

## Upgrade Notes

- No changes are needed on the router. If you reinstall, you get the same behavior.
- Maintainers: import the repository into SonarQube Cloud, turn off Automatic
  Analysis, and add the `SONAR_TOKEN` secret so the scan runs.
