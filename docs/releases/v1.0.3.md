# v1.0.3 - Agent Tooling, Tag-Triggered Releases, and Dependency Refresh

## Summary

This release rounds out the multi-agent tooling surface (Claude Code and Gemini CLI
entrypoints alongside the existing Copilot mirrors), automates GitHub Release
publishing from a pushed `v*` tag instead of a hand-run `gh release create`, and
refreshes every outdated CI/pre-commit/test-image dependency pin to current stable.

## Why This Change

- Claude Code and Gemini CLI had no auto-loaded project entrypoint, so none of
  `AGENTS.md`'s rules (quality gate order, coverage floor, SRM shell invariants)
  were being surfaced automatically in those tools' sessions.
- Publishing a release required manually authoring and running
  `gh release create` after tagging, with no guardrail tying the tag, `VERSION`,
  and the release-notes file together.
- Several CI, pre-commit, and test-image pins (GitHub Actions, `pip`, `ruff`,
  `markdownlint-cli`, `pre-commit-hooks`, the Debian test-image base/snapshot,
  `bats-core`) had drifted behind current stable releases.

## What Changed

### 1. Claude Code / Gemini CLI Entrypoints

- Added [`CLAUDE.md`](../../CLAUDE.md) and [`GEMINI.md`](../../GEMINI.md) as thin
  pointers into [`AGENTS.md`](../../AGENTS.md) — no duplicated rules, following the
  same pattern as the existing `.github/` Copilot mirrors.
- Updated `AGENTS.md`'s Agent Surface Map with both new files.

### 2. Tag-Triggered GitHub Release

- Added [`.github/workflows/release.yml`](../../.github/workflows/release.yml):
  triggers on `v*` tag push, fails closed if `VERSION` doesn't match the tag or
  `docs/releases/<tag>.md` is missing/malformed (H1 must start with the tag; body
  non-empty), installs a pinned `gh` CLI, then runs `gh release create --verify-tag`
  using the notes file's H1 as the title and the rest of the file as the body.
- Updated the `prepare-release` skill: once `VERSION` and
  `docs/releases/vX.Y.Z.md` are committed, `git tag vX.Y.Z && git push origin
  vX.Y.Z` is now the only remaining step — no more hand-run `gh release create`.

### 3. CI / Pre-commit / Test Image Dependency Refresh

- GitHub Actions: `actions/checkout` v7 → v7.0.1, `docker/setup-buildx-action`
  v4.2.0 → v4.3.0 (both re-pinned to immutable commit SHAs).
- Python/Node tooling: `pip` 25.2 → 26.2.1, `ruff` 0.15.22 → 0.16.4,
  `markdownlint-cli` 0.41.0 → 0.49.1, `actions/setup-node` v7.0.0 (Node 22.23.2),
  `pre-commit-hooks` v5.0.0 → v6.0.0.
- Test image (`tests/Dockerfile`): `debian:bookworm-slim` base digest and APT
  snapshot date refreshed (2026-08-25 → 2026-08-26), Node.js 22.18.0 → 22.23.2,
  `bats-core` v1.13.0 → v1.14.0.
- `yamllint`, `shfmt`, `shellcheck`/`shellcheck-py`, `PSScriptAnalyzer`, and `kcov`
  were already at current stable — left unchanged.

### 4. Validation

- Quality gate (`tools/runners/quality.sh`, plus `markdownlint@0.49.1` run
  standalone) passed clean.
- Rebuilt the `srm-mock` test image on the refreshed base digest/snapshot/tool
  pins and ran the full Dockerized BATS suite (unit + component + e2e) with kcov —
  all 21 tests passed.
